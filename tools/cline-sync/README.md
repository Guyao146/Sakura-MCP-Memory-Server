# Sakura Cline Sync

把 Cline 的本地对话历史定时同步到 Sakura-MCP-Server，自动抽取长期记忆。托盘常驻 + 本地配置面板，不需要手动触发。

## 它解决什么问题

MCP 是「工具」而非「监听器」：服务端看不到你和模型的对话，只有客户端主动调用工具时才写入。靠 `.clinerules` 让模型自己在结尾调 `memory_extract_and_remember` 并不可靠——模型会忘。

本工具改为读取 Cline 落盘的对话历史，定时增量推送，是文件级的硬采集，不依赖模型自觉。

## 与同类方案对比

| 能力 | Mem0 / Zep / Basic Memory 这类记忆服务端 | `.clinerules` 让模型自己调工具 | 本工具（客户端采集层） |
| --- | --- | --- | --- |
| 定位 | 存什么、怎么去重、怎么检索 | 让模型在对话结尾自觉写入 | 负责把对话可靠地送进去 |
| 采集可靠性 | 依赖应用层主动写入 | ❌ 模型经常忘 | ✅ 文件级硬采集，落盘即同步 |
| 增量去重 | 时间线 / ID 游标 | ❌ 无 | ✅ 按 taskId 游标，只推新增 |
| 隐私脱敏 | 部分有 | ❌ 无 | ✅ 上传前默认脱敏 |
| 成本可见 | 用量面板 | ❌ 无 | ✅ 运行前估算 + 累计统计 |
| 开机自启常驻 | Dropbox 类客户端有 | ❌ 无 | ✅ 托盘一键开启 |
| 失败熔断 | 有 | ❌ 无 | ✅ 连续失败自动暂停，避免空打 |
| 启动即同步 | 有 | ❌ 无 | ✅ 过期立即补同步 |

Mem0 / Zep / Basic Memory 与本工具不是竞争关系：它们是「记忆服务端」，在本体系里由 Sakura-MCP-Server 服务端承担（向量库、冲突检测、自动合并、空间隔离）；本工具补的是它们都缺的一环——把对话从本地磁盘可靠地送进服务端。

## 工作方式

```text
定时扫描 Cline 任务目录
  → 按 taskId 对比游标，只取新增消息
  → 脱敏（默认开启）
  → 调用 memory_extract_and_remember，由服务端抽取并入库
  → 成功后推进游标；失败保持原位，下次重试
```

Cline 的历史目录（Windows）：

```text
%APPDATA%\Code\User\globalStorage\saoudrizwan.claude-dev\tasks\<taskId>\api_conversation_history.json
```

macOS 与 Linux 会自动换成对应的 `globalStorage` 路径，也可以在面板里手动指定。

## 安装与运行

### 方式一：单文件 exe（推荐）

```bash
cd tools/cline-sync
npm install
npm run package
```

产物在 `release/cline-sync.exe`（约 95 MB，内置 Node 22 运行时与托盘辅助程序），双击即可运行，目标机器无需安装 Node.js。默认只构建 `node22-win-x64`；要交叉编译其他平台，改 `package.json` 里 `pkg.targets`，例如：

```json
{ "pkg": { "targets": ["node22-win-x64", "node22-macos-arm64", "node22-linux-x64"] } }
```

首次启动时，内置的托盘辅助程序会从只读快照解包到 `%APPDATA%\sakura-cline-sync\traybin\`，之后复用。

### 方式二：从源码运行

```bash
cd tools/cline-sync
npm install
npm run build
node dist/main.js
```

开发期直接用 `npm run dev`（tsx，无需先编译）。

首次启动会打印配置面板地址，例如 `http://127.0.0.1:53124/?token=...`。若尚未配置 MCP 地址与密钥，程序会自动弹出配置窗口；之后可从托盘菜单点「打开配置窗口」再次打开。

## 开机自启

托盘菜单的「开机自启」会把当前 exe 注册到登录时启动，三平台各自走原生机制：

- **Windows**：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `SakuraClineSync`。
- **macOS**：`~/Library/LaunchAgents/org.sakura.cline-sync.plist`（`RunAtLoad`）。
- **Linux**：`~/.config/autostart/sakura-cline-sync.desktop`（XDG 规范）。

该菜单项只在打包后的 exe 里可用：从源码运行时入口依赖工作目录和 PATH 上的 node，注册了也不可靠。勾选状态在启动时自动检测。

## 运行历史与失败保护

每次同步都会写入 `%APPDATA%\sakura-cline-sync\history.json`（最近 50 次运行 + 累计计数器），配置面板的「状态」区显示累计同步任务数、推送消息数、抽取调用数和失败任务数，重启后不丢。

连续失败保护（熔断）：当某次同步**一条都没成功**（失败数 > 0 且成功数为 0，或整个同步抛错）时计一次连续失败；**连续 3 次**后自动暂停定时器，并在配置面板顶部显示告警横幅，避免对已下线或已失效的服务端每周期空打。点横幅里的「恢复自动同步」，或通过托盘暂停/恢复，即可清零并重新排程。个别任务失败（比如某个任务触发了权限错误而其他任务正常）不会触发熔断。

## 并发与资源回收

- 同一客户端进程内只允许一个同步任务执行；重复点击不排队，扫描采用「完成后再等待一个间隔」，不会在慢请求期间堆积定时任务。
- 暂停、修改配置或退出时会取消旧同步的网络请求和后续文件扫描，释放请求超时计时器与取消监听器。取消不计入连续失败熔断。
- 已确认上传成功的任务仍保存游标；被中断的上传不推进游标，下次重试。取消客户端请求不能撤回服务端已经完成的写入。
- 配置窗口在存活时复用，避免反复点击启动新窗口；关闭客户端时回收它启动的独立窗口进程树和托盘辅助进程，不结束用户日常浏览器。退回默认浏览器时不会主动关闭浏览器。
- 面板的任务扫描、连接测试和配置保存分别限制同类并发；页面断开或客户端退出时取消在途扫描/测试，退出时关闭 HTTP 连接、托盘刷新计时器和信号监听器。
- 这里治理的是异步任务、计时器和子进程的生命周期，并非手工缩减 Node.js 内部线程池。多个独立启动的客户端进程之间尚未加跨进程锁。

## 配置窗口

配置界面以独立桌面窗口打开，无地址栏、无标签页，看起来就是一个普通应用窗口。实现方式是复用机器上已安装的浏览器引擎（Windows 优先 Edge/WebView2，其次 Chrome；macOS 与 Linux 同理），以 `--app` 模式启动，因此不需要打包 Electron，exe 体积不受影响。

窗口使用位于 `%APPDATA%\sakura-cline-sync\panel-profile\` 的独立配置目录，与你日常浏览器会话隔离——面板地址里的 token 不会进入浏览历史，也不会被已打开的浏览器窗口接管。

若机器上找不到可用引擎，会退回用默认浏览器打开同一地址，功能完全一致。

## 配置项

| 项 | 说明 |
| --- | --- |
| MCP 地址 | `https://<你的域名>/mcp` |
| Agent 密钥 | 后台「Agent 密钥」创建，需 `memory:write` 权限，且必须为目标空间「授权空间」 |
| Cline 任务目录 | 留空自动检测 |
| 扫描间隔 | 默认 10 分钟，1–1440 |
| 忽略早于 | 默认 30 天，0 表示不限 |
| 上传前脱敏 | 默认开启 |
| 启用自动同步 | 关闭时只能手动触发 |
| 选择方式 | `全部` / `仅同步勾选的任务` / `排除勾选的任务` |

配置与游标存放位置（Windows）：`%APPDATA%\sakura-cline-sync\`，其中 `config.json` 含密钥，以 `0600` 权限写入。

## 任务选择

配置面板的「任务选择」区列出磁盘上的每个 Cline 任务，显示最后活动时间、总消息数、待推送消息数、上次同步时间，以及本次是否会同步。底部汇总选中的任务和待推送消息；长对话会分块，实际抽取调用数可能大于任务数。

三种模式：

- **全部**：同步时间窗口内的所有任务（默认）。
- **仅同步勾选的任务**：白名单。空列表表示不同步任何任务，而不是回退成同步全部——这是刻意的，避免误配置导致意外全量上传。
- **排除勾选的任务**：黑名单。

时间窗口优先于选择：被「忽略早于」排除的任务即使勾选也不会同步，列表中显示为「超出时间范围」。

## Agent 权限

Agent 有两层权限，必须同时满足才能写入：

1. 全局 scopes：创建 Key 时勾选 `memory:write`。
2. 空间级授权：在后台「Agent 密钥」中点该 Key 的「授权空间」，选择目标空间并勾选 `memory:write`。

只有第 1 层会导致同步报 `Agent is not granted memory:write in this space.`。失败的任务不会推进游标，补齐授权后重试即可，不会漏数据。

## 托盘菜单

打开配置窗口、立即同步、状态显示（每 5 秒刷新）、暂停/恢复自动同步、开机自启、退出。若系统不支持托盘，程序会退回控制台模式继续运行而不是退出。

## 安全说明

- 配置面板只监听 `127.0.0.1`，且每次启动生成随机 token，网络上无法访问。
- 面板返回配置时密钥是掩码的；提交时留空即保留原值。
- 脱敏覆盖 `sk_sakura_`、`sk-`、`ghp_`、`xox*`、`AKIA`、JWT、`Authorization: Bearer`、PEM 私钥块，以及 `password=`/`token:` 这类键值对。这是尽力而为的防护，不是保证——本工具会把整段对话送去抽取，敏感项目请谨慎启用。
- 认证走 Agent 密钥（Bearer），不涉及 OAuth 与动态客户端注册。

## 成本提示

`memory_extract_and_remember` 每次调用都会消耗服务端配置的 Chat Provider 额度。对话先脱敏，再按最多 200,000 个 UTF-16 字符分块；不再只上传末尾。每块成功确认后原子保存游标，超长单条消息会记录偏移及内容哈希，重启后继续未确认的部分。末尾只有一条新消息也会上传。

面板累计抽取调用数包含失败请求；长对话可能每次扫描产生多次调用。想更省可以把扫描间隔拉长，或把「忽略早于」调小。

同步采用至少一次提交：服务端已成功但响应丢失，或进程在保存断点前崩溃时，最后一块可能重传。正在续传的消息若被修改，会从该消息开头重新发送以避免漏内容。旧版本已截断并标为完成的历史不会自动补传；需要补传时先备份游标，再移除对应任务的记录。
