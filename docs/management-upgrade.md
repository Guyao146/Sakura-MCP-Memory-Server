# 工作区管理与可靠性增强（v0.5.0）

本批次在 `v0.4.1` 基础上开发，应用版本为 `0.5.0`。GitHub Release 与镜像是否可用以对应标签的 Actions 结果为准。

## 升级与兼容

- 先备份数据库、原 `CONFIG_ENCRYPTION_KEY`、runtime-secrets 卷及部署配置。
- 新迁移 `016_management_reliability.sql` 增加配额计数、每日调用统计、可重放导入明细、邀请撤销和会话已验证邮箱。
- 迁移会扫描已有记忆初始化用量；大库应在维护窗口执行。旧的未完成同步导入会标记失败，须重新提交原文件。
- 旧会话仍可使用，但接受邮箱邀请需要重新通过外部 OIDC 登录取得本次已验证邮箱；本地账号资料邮箱不作为邮箱所有权证明。
- 原 MCP 和管理 API 保持；新增功能位于「工作区管理」。原同步导入仅用于兼容，新页面使用持久化队列。
- Dockerfile 已加入移除运行时 npm/corepack/yarn 的步骤，仍需重建验证；入口直接执行 Node，后续精简容器中的运维命令请使用 `node`，不要使用 `npm`。已发布镜像不受当前工作树修改影响。

## 功能与边界

### 记忆管理

- 按空间、关键词、类型、标签、状态筛选，按创建时间/重要度排序，30 条一页。
- 同空间批量归档、软删除、恢复，每次最多 100 条。新页面永久删除要求空间管理员且记录已在回收站中；旧 MCP `memory_forget(permanent=true)` 保留管理员直接永久删除的兼容语义，使用前请确认备份。
- 版本历史 50 条一页，显示字段级差异。恢复新增版本，不删除历史；恢复正文会使旧向量失效，按需执行向量重建。
- 回收站恢复默认激活记录；版本恢复保留快照中的业务状态、有效期、重要度等字段。
- 成员移除后，其 Agent 的该空间授权同时删除；不删除记忆。

### 导入与导出

- JSON/Markdown 文件预检、完全相同正文的重复检测；默认跳过重复，可选择保留。
- 每任务最多 500 条 / 5 MB，任务与原文落库。Worker 对每条记录在同一事务中写入记忆及完成标记，重试不会再次写入已完成项。
- Worker 关闭时拒绝新页面提交；取消在下一条记录前检查，已提交记录保留。部分失败可查看明细并重试，已完成/跳过的项不重放。
- 原同步导入可取消，但缺少原文的历史任务不可重试。达到保留期清理原文后，新任务同样不能再重试。
- JSON 内容交换保留状态和来源，不恢复原 ID、版本历史、空间成员及关系；不能替代数据库备份。Markdown 是有损内容交换格式。
- Web 导出流式传输，每批 16 条，上限 50000 条 / 256 MiB，JSON 尾部 `truncated` 或 Markdown 尾注说明截断；开始下载后故障会中断响应，不声称成功。
- MCP 兼容导出返回字符串，限制 16 MiB，超出拒绝而非耗尽内存。分页游标用数据库文本时间戳保留微秒。

### 成员与权限

- 创建邀请仍在「记忆空间 → 成员」；新页提供接受、查看、撤销邀请。
- 接受邀请不会覆盖已有成员的角色。管理员不能修改所有者或其他管理员，所有者可管理角色、转移所有权；共享空间始终保留至少一名所有者。
- 个人空间不允许通过成员管理转移或删除所有者。
- 用户仅管理有权限的空间；系统指标/清理仅系统管理员可访问。空间配额目前要求系统管理员同时是空间所有者。

### 运行状态与配额

- 展示数据库体积、进程内存/运行时间、队列状态、向量状态、Provider 调用数/失败数/耗时。
- 可限制未删除记忆条数、正文字节、每日 Provider 请求数；默认为不限。配额不是 token 计费，批量请求计一次；按数据库日期重置。
- 数据库触发器原子维护用量，覆盖 Web、MCP、导入和恢复；已超限空间仍允许减少用量。
- Provider 状态统计是进程级，重启清零；空间每日统计持久化。重建过程中缺少权限、配额耗尽或服务失败可能留下待重建向量。
- 审计文件 10 MiB 轮转并保留 5 份；多实例必须分别使用独立文件路径。数据库清理由管理员确认执行，保留 30–3650 天，一批最多 10000 条审计及 100 个已终结任务的原文；可重复执行直至清空到期数据。清理和重试在同一任务锁下互斥，不会自动删除记忆或回收站。
- Provider 调用归属预留配额时的数据库日期；跨午夜完成仍写回该日期。配额预留后取消的请求保守计入当日额度。
- MCP 增加 `memory_browse`、`memory_history` 和 `memory_import_queue`；前两者继续校验实时 Agent 空间授权，持久化导入暂仅开放给人工凭据。Agent 列表支持分页和撤销单空间授权。

## 代理与浏览器安全

- `TRUST_PROXY=true` 仅用于应用只接受可信反向代理的部署。单层 Nginx 必须覆盖 `X-Forwarded-For $remote_addr`，不得保留客户端转发链；多代理应先显式配置可信 real_ip 来源。
- 更新 Nginx 示例后重新检查配置并重载：补齐 `/api/me/` 和 `/assets/management.js`，为 `/api/admin/exports` 禁用代理缓冲并设置下载超时。
- CSP 脚本采用静态 SHA-256 白名单，不允许任意内联脚本；样式仍允许内联。部署代理不要改写 HTML/script 内容，否则哈希失效。

## 离线数据库备份与恢复

工具需要 Node、项目依赖和匹配数据库版本的 PostgreSQL 客户端；数据库需预装 pgvector 扩展文件。工具在源码工作目录运行，不在精简应用容器内运行。

1. 安全设置 `DATABASE_URL` 环境变量，避免命令行参数/日志暴露密码。必要时通过 `PG_DUMP` / `PG_RESTORE` 指定客户端可执行文件绝对路径。
2. 用 `node scripts/backup.mjs create <新的绝对目录>` 创建数据库 custom dump 与 SHA-256 manifest。目录必须不存在。
3. 用 `node scripts/backup.mjs verify <绝对目录>` 校验文件大小与摘要。
4. 另行离线备份原 `CONFIG_ENCRYPTION_KEY`、runtime-secrets、Compose/.env 配置及所需审计文件。工具不自动输出或复制密钥。丢失原密钥无法解密已有 Provider/Agent 密钥。
5. 恢复演练必须创建**全新的隔离空数据库**，停止所有连接该目标的应用进程，再将 `DATABASE_URL` 指向目标。
6. 执行 `node scripts/backup.mjs restore <绝对目录> RESTORE_INTO_EMPTY_DATABASE`。非空目标拒绝恢复；使用单事务、遇错停止，不执行 `--clean` 或 DROP。
7. 恢复原主密钥与配置，在隔离网络核对迁移列表、用户/空间/记忆数量、历史版本与抽样检索，再决定切换。不要把生产备份发给未经授权的人员。

备份含私密原文和凭据哈希，**不是加密文件**；使用磁盘/归档加密和受限权限保管。SHA-256 只检测完整性，不认证来源：只恢复可信备份。Windows 应额外配置目录 ACL。

- `npm run check`、`npm run build`。
- `DATABASE_TEST_URL` 仅指向全新可丢弃 pgvector 测试库运行集成测试；绝不指向生产库。
